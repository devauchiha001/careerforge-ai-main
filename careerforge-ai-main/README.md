# CareerForge AI

AI-powered job application and career optimization platform.

## Features
- **Google sign-in** (popup, with automatic redirect fallback when popups are blocked)
- **Resume Analyzer** — upload a PDF/TXT or paste text; parsed in the browser, scored on 10 ATS-readiness checks, skills and contact details extracted
- **Job Match** — paste a job description to get a resume/job fit estimate, matched/missing skills, missing keywords and recommendations
- **AI Application Builder** — cover letter, recruiter message, tailored resume summary, interview prep, application introduction, and a “why hire me” answer, written by Gemini via Firebase AI Logic (falls back to smart templates if AI Logic isn't enabled)
- **Related Jobs** — real listings from Jobicy and Himalayas, locally deduplicated and ranked against profile/resume data with transparent CareerForge Match Scores, location preference support, per-source status, and provider attribution
- **Saved Jobs** — save, annotate, mark as interested/applied, and create or update a corresponding application tracker entry
- **Application Tracker** — create, edit, filter, search and delete applications across Saved → Applied → Interview → Offer / Rejected
- **Career Profile** — editable target roles, country/region/city, preferred locations, work-mode preferences, experience, education, technical skills, and soft skills
- Light / dark mode, fully responsive

## Stack
- React + TypeScript + Vite
- Firebase Authentication (Google) and Realtime Database
- Gemini via Firebase AI Logic (`firebase/ai`)
- pdf.js for in-browser PDF parsing

## Architecture
- Pages in `src/pages` use shared components from `src/components` and application state/routing from `src/hooks`.
- Firebase Auth and Realtime Database logic live in `src/lib`; per-user data is stored below `users/{uid}`.
- Job discovery is modular under `src/services/jobs/providers`; provider-specific adapters normalize real feeds into `JobPosting`. `jobSearch.ts` aggregates providers, isolates failures, deduplicates records, and caches pages. Jobicy is fetched from the browser; Himalayas is fetched by the authenticated Firebase callable function because its API blocks browser CORS.
- Job listings are fetched from Jobicy and Himalayas. They are not generated by AI; source names and source links are retained through deduplication. Both feeds supply remote roles. Himalayas location is marked matched only when the user's exact profile country appears in the provider's explicit restrictions; otherwise eligibility remains unverified.
- Profile location, work-mode, experience, education, skills, role, and seniority preferences inform ranking. Location and source filters run locally. “Eligibility not verified” means the source did not establish the user's right to work from their selected location; users should verify on the source listing.
- CareerForge Match Score separately weighs skills (24%), job-title similarity (14%), keywords (14%), experience (10%), education (8%), location (12%), work mode (10%), and seniority compatibility (8%). It is a transparent heuristic, not an employer ATS score. Missing requirement data receives a neutral score.
- The browser caches the public feed for six hours to reduce requests. More provider pages are loaded only when the user requests them. Search filters and ranking run locally; resume/profile data is not sent to the job feed provider.

## Environment
Copy `.env.example` to `.env` and add your Firebase web-app configuration. If required variables are missing, the app shows a setup screen instead of crashing.

Related Jobs does not require a job-provider API key. Jobicy is called directly; Himalayas requires the authenticated Firebase Function deployed below because the browser is blocked by CORS. Job availability, licensing scope, and geographic coverage depend on the providers' current terms and listings. Salary is displayed/sorted only when the source provides it; reported salary sorting does not convert currencies.

## Firebase setup
1. **Authentication** → Sign-in method → enable **Google**. Add your deployed domain under *Authorized domains*.
2. **Realtime Database** → create a database, then deploy the included rules (each user can only access `users/{their uid}`). Deploy the Himalayas adapter function with the rules:
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase use <your-project-id>
   npm --prefix functions install
   firebase deploy --only functions,database
   ```
   The callable is in `functions/src/index.ts`, requires Firebase Authentication, validates pagination cursors, and has bounded request timeouts and instance count. It uses the public Himalayas endpoint and has no API key. Cloud Functions deployment may require a billing-enabled Firebase plan and incur usage charges; check your project plan before deployment.
3. *(Optional)* **AI Logic** → enable the Gemini Developer API to get AI-written documents. Override the model with `VITE_GEMINI_MODEL` if needed.
4. *(Optional)* Deploy hosting: `npm run build && firebase deploy --only hosting`.

## Data model (Realtime Database)
```
users/{uid}/profile            displayName, headline, targetRoles[], country, region, city, preferredLocations[], remotePreference,
                               experienceLevel, yearsExperience, education, technicalSkills[], softSkills[]
users/{uid}/resume             fileName, text, skills[], score, checks[], contact
users/{uid}/analyses/{id}      jobTitle, company, score, matched/missing skills & keywords, generated docs
users/{uid}/applications/{id}  company, role, status, url, location, appliedOn, notes
users/{uid}/savedJobs/{jobId}  normalized public listing, status, notes, savedAt, updatedAt
```

## Security and data handling
- Never commit `.env` or service-account credentials. Firebase browser configuration is client-visible; Realtime Database rules enforce per-UID access.
- Deploy the updated `database.rules.json` after changing the database schema so users can save jobs.
- Resume text is used locally by the match-ranking code and is not sent to Jobicy. When Gemini document generation is invoked, resume and job-description content is sent through Firebase AI Logic.
- Job listings and posting/application links come from the named providers. The app does not scrape job boards or generate job listings. Some provider links lead to the provider listing page rather than directly to an employer application form.
- No job-provider API key is used or required. Do not create `VITE_JOBICY_API_KEY` or a Himalayas key variable. `.env.example` lists Firebase variable names with blank values; never copy real credentials into source control.
- Himalayas terms were not independently re-reviewed against the user's license document; implementation assumes the user's confirmed permission covers display, attribution, and the six-hour browser cache. Confirm that its scope includes the actual deployment, audience, and content fields.

## Current limitations
- The sources currently cover remote roles and do not aggregate every employer or job board. Jobicy supplies remote listings; the current Himalayas endpoint integration also normalizes remote listings.
- Himalayas requests require a deployed Firebase Function and authenticated user. This local source/build check does not prove the function has been deployed or that authenticated live integration works.
- Neither source guarantees city/country coverage or employer-direct application URLs. Verify eligibility on the original posting. Unreported location eligibility remains explicitly unverified; remote does not mean worldwide.
- Match scores are transparent heuristic estimates, not actual employer ATS scores or hiring decisions. Missing data is treated neutrally.
- Firebase rules must be deployed using `firebase deploy --only database`; successful local build does not prove remote Firebase access or rules behavior.
- Job availability and URLs can change at the source. Always confirm details and eligibility on the original listing.
- The browser cache is device-local, while saved-job records are stored in the signed-in user's Firebase workspace.
